Add cross-node query/report fan-out gateway for partitioned tenants

- picowal_partition: new picowal_partition_fetch() (raw HTTP round trip
  to any node, not just an owner) and picowal_partition_all_nodes()
  (enumerate a tenant node pool for fan-out), refactored proxy() to
  share the round-trip core (pp_http_roundtrip).
- api.c: /wal/query and /wal/report now fan out to every node in the
  tenant partition pool (self served in-process, peers over HTTP) and
  merge the internal {"rows":[...],"count":N} shard results into one
  response. Missing/unreachable shards degrade gracefully via
  partial/shards_ok/shards_total fields instead of failing the whole
  query; only fails if every shard is unreachable.
- New X-PW-Partition-Hop request header (parsed in http.c, threaded
  through api_dispatch/dispatch_picowal as is_partition_hop) stops a
  forwarded query from re-fanning-out on the receiving node.
- Fixed a header-length bug (X-PW-Partition-Hop is 18 chars, not 19)
  that caused an infinite fan-out loop/deadlock across all 3 nodes
  during initial testing.
- Extended test_picowal_partition.sh with a query-gateway section
  (10/10 checks green); test_picowal.sh and test_picowal_wal.sh still
  green (no regressions).
